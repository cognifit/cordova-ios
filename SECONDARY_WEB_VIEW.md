# Secondary web view

The main app uses `cordova.secondaryWebView`. It replaces the removed `CDVViewController` web-view-clone API, `CDVGameViewController`, and game-host script. Android likewise removed the `CordovaActivity`/`IndependentWebViewHost` clone API. It exposes `getCapabilities()`, `create(config)`, `destroy()`, `setTouchRegions({mode, rects})`, `send(envelope)`, `post(name, payload)`, `request(name, payload)`, `onEvent(listener)`, and `getMetrics()`. Calls return promises. `create` resolves to `{sessionId, storageIsolation}` and rejects with `{code, message}`. Create again only after `destroy`.

## Configuration

`url` is required and names a local bundle-relative or `file://` document. Optional keys: `zOrder` (`below` default, or `above`), `opaque` (`false`), `backgroundColor` (`transparent`), `frame` (`fill` or CSS-pixel `{x,y,width,height}`), `hardwareAccelerated` (`true`), `processIsolation` (`shared`), `storageIsolation` (`origin` default, or `ephemeral`), `allowedRoots` (default: containing directory, entries `{path,kind:'bundle'|'file'}`), `maxParallelAssetReads` (unbounded or positive integer), `assetReadTimeoutMs` (`5000`), `assetReadWatchdogMs` (`60000`, range `1000`–`300000`), `assetCacheMaxAgeSeconds` (`3600`, range `0`–`31536000`), `followSymlinks` (`false`), `heartbeatMs` (`2000`, `0` disables; positive values below `500` are clamped to `500` in page and native timers), `telemetry` (`{counters:true,perRequest:false,assetErrors:false}`), and `protocolVersions` (all supported). Colors use `transparent`, `#RRGGBB`, or `#RRGGBBAA`; `opaque:true` requires an opaque color. Invalid or unsupported modes return a typed error. The capability probe reports the default achieved mode, `storageIsolation:'origin'`, and `processIsolation:false`. Requesting `ephemeral` uses a nonpersistent WKWebsiteDataStore and returns `ephemeral` from `create`.

The content URL is `secondary-content://localhost/r/<rootIndex>/<relativePath>`, a distinct origin from the main view's scheme. The scheme handler serves only paths inside declared roots. `ephemeral` uses a nonpersistent `WKWebsiteDataStore`; `origin` uses the default persistent store while retaining the distinct scheme origin. `none` is unsupported because the secondary always has a separate origin. The secondary has no Cordova plugin bridge. Its sole global is `window.secondaryWebView`, with `request(name,payload)`, `post(name,payload)`, `subscribe(streamName,{rateHz,coalesce})`, `unsubscribe(id)`, `on(name,fn)`, and `onMessage`. The host decides how to answer requests; it can send a `res` envelope with the same `id`.

On iOS 16.4 and later, the secondary copies the main WKWebView's current `isInspectable` value before its first load. It appears in Safari Web Inspector when the main view is inspectable, including when inspection was changed through `InspectableWebview`. Asset-failure logs include the requested path relative to its declared root, so a missing or denied file can be identified without logging the root's absolute path.

The envelope is `{v,id,kind:'req'|'res'|'evt',name,payload,err?}`. Version 1 is supported. Each native event includes `sessionId` and `type`. Events: `ready`, `firstPaint`, `loadFailed`, `assetError`, `terminated`, `unresponsive`, `responsive`, `destroyed`, `memoryPressure`, `message`, `channelError`. `streams` is a secondary-facing event with one payload map of subscription IDs to `{streamName,data}` per display frame. The hard subscription rate cap is 60 Hz.

Native producers import `<Cordova/CDVSecondaryWebViewStreams.h>` and call `[CDVSecondaryWebViewStreams pushSample:sample streamName:name]` from any thread. `[CDVSecondaryWebViewStreams hasSubscriberForStream:name]` reports whether a secondary currently subscribes to that name, so producers can stop sensors when it becomes false. Neither call needs a plugin instance. A push without a secondary or subscriber is a cheap no-op. Samples must be JSON values: `NSString`, finite `NSNumber`, `NSNull`, `NSArray`, and `NSDictionary` with string keys (or `nil` for JSON null). Invalid values, including non-finite numbers anywhere in the value, are dropped and emit host `channelError` with `INVALID_JSON` while subscribed. The older `CDVSecondaryWebView` instance `pushSample:streamName:` remains for compatibility and delivers only to that instance; new producers should use the public class API. Secondary pages use `subscribe(name,{rateHz:1..60,coalesce:'latest'|'batch'})`; `latest` keeps the newest sample, while `batch` retains samples in order. Delivery emits at most one `streams` event per display frame with a 60 Hz hard cap. Backgrounding, renderer termination, and destruction clear subscriber state. `CDVViewControllerTest.testSecondaryNativeStreams` covers background-thread delivery, coalescing, rate limiting, invalid samples, background clearing, and destroy.

The public producer rate query (`maximumRateHzForStream:` on iOS, `maxRateHz` on Android) is thread-safe and returns the highest subscribed `rateHz` for a stream across live secondary views, or `0` with no subscriber, while backgrounded, after renderer termination, and after destroy. Producers can use it to set their sensor sampling period. When every subscriber to a stream uses `latest`, the public push path drops samples arriving sooner than 90% of one period at that maximum rate after the last accepted sample. The gate uses a monotonic clock and runs before JSON validation, copying, queueing, and Android isolated-process transport. A gated-out invalid sample is silently dropped; an invalid sample that passes the gate still reports `INVALID_JSON` without consuming a gate slot. If any subscriber uses `batch`, every sample passes the gate and batch order is preserved. A `latest` consumer may observe a value up to one period old. Android isolated mode mirrors subscribed rates and coalescing modes to the host along with stream names; pause, resume, service death, and destroy clear that mirror.

Touch mode defaults to `none`; only the main view can set `rects` or `all`. Routing applies to either z-order, and a region update cancels an active gesture. Cancellation uses a separate recognizer on each web view, never their shared parent. Normal touch completion and cancellation reach a terminal state, `reset` clears recorded touches, and background/foreground transitions disable/reset the recognizers before tracking resumes. UIKit retains the original target for the existing touch sequence; region updates cancel its native gesture and the next touch uses the new routing. This suppresses native tap recognition; it does not promise a DOM `touchcancel` event from WebKit. Asset responses use `Cache-Control: private, max-age=<assetCacheMaxAgeSeconds>`; set the age to `31536000` for immutable content. Missing, denied (including outside a root or a blocked symlink), permit-timed-out, and watchdog-expired reads return HTTP 404, 403, 503, and 504 responses with a short `text/plain` body and `Cache-Control: no-store`. They complete as responses for `fetch`, synchronous XHR, and asynchronous XHR. Only a failed entry document emits `loadFailed`; subresource failures do not destroy, reload, or retry the session. An unexpected file or internal error returns 500. The iOS handler cancels tasks when the session is destroyed; it does not emit a 410 because stopped WebKit tasks cannot receive callbacks. (Android can return 410 for a request that races destruction.) Text, JavaScript, JSON, and SVG responses declare `charset=utf-8`. Byte-range (`Range`) requests are not implemented, so media seeking should not rely on this origin. The handler buffers each asset before sending HTTP 200 so a read timeout can still return 504; this uses memory proportional to the asset size. A canceled or stalled read releases its permit. Backgrounding clears subscriptions and pauses heartbeat monitoring; foregrounding resumes monitoring. A memory warning emits `memoryPressure`. WebKit content-process termination emits `terminated` without reloading; the host decides when to destroy and recreate. Destroy removes handlers, views, subscriptions, and timers.

Set `telemetry.assetErrors:true` to receive host `assetError` events. Each event uses the standard envelope `{sessionId,type:"assetError",detail}`, where `detail` is `{sessionId,path,rootIndex,status,reason}`; `path` is relative to the requested root and `rootIndex` is -1 when the URL has no valid root number. Identical `(rootIndex,path,status,reason)` failures are emitted once per one-second window, with at most ten distinct events per window; suppressed events still increment the existing counters. The fork applies no policy on these failures. Hosts can use `assetError`, heartbeat, `unresponsive`, and `terminated` to decide whether to retry, reload, or destroy. The sample app's `www/secondary-http-status-host.html` creates the secondary with this opt-in and checks `assetError` emission and the absence of `loadFailed` for subresources. Its secondary `www/secondary-http-status.html` checks missing (404) and denied (403) requests through `fetch`, synchronous XHR, and asynchronous XHR.

Channel validation uses three distinct codes in both directions. `INVALID_JSON` means an envelope contains a non-finite number (`NaN`, `Infinity`, or `-Infinity`) or another value that cannot be represented as JSON, including one nested in an array or object. `MESSAGE_TOO_LARGE` means valid JSON exceeds the 1 MiB UTF-8 channel limit. `INVALID_MESSAGE` means malformed JSON or wire data, a malformed envelope or packet, or an application attempt to use the reserved `__secondaryChannelError` message name. Explicit top-level `undefined` payloads become `null`; nested `undefined` is `INVALID_JSON`. Host `send`, `post`, and `request` reject with `{code,message}`. Secondary-page `request` rejects with the same code and reports host `channelError`. Secondary-page `post` remains fire-and-forget and returns `undefined`; failures emit host `channelError` and `console.warn` in the page, without an unhandled rejection. Internal posts also swallow transport rejection during teardown or backgrounding. Validation failures do not end the session. The sample `secondary-channel-validation-host.html` and its secondary page exercise both directions, the size boundary, malformed input, reserved name, undefined payloads, and a subsequent successful message.

## Scheme-handler threading

WebKit starts and stops scheme tasks on the main thread. The handler keeps active-task and lease maps on that thread; stop and destroy remove tasks from those maps immediately. Permit admission and release run on the main thread. Waiting reads stay in a FIFO queue with a main-thread timeout; no reader thread waits for a permit. File reads run on a background queue, and only that reader closes its file descriptor, including at EOF. The watchdog marks the lease expired and queues a 504; it does not close the descriptor. A lease uses a short internal lock only for its valid, complete, and expired flags. Every `WKURLSchemeTask` response/data/finish callback is dispatched to the main queue, checks that the task is still active before each call, and runs without holding a lock. The read watchdog can expire a lease and queue an HTTP 504 without waiting for a stalled read. A stopped task receives no further callbacks.

The sample app's `www/secondary-deadlock-stress-host.html` starts 288 image and asynchronous XHR requests in one turn, then synchronous XHR, element removals, and iframe navigations. A second round starts 1,024 asynchronous requests and destroys the secondary during loading. `getMetrics().activeSchemeTasks` reports the current main-thread task count; the test fails if it cannot observe a pending task before destroy. The host tests both JavaScript timer gaps and native bridge round trips, failing either when delayed more than one second. The test also rejects `NSNull` numeric/boolean create fields, sends an invalid `rateHz`, and sends a 600 KiB channel event while the host polls metrics. It has a 20-second deadline, and destroy logs the number of active scheme tasks it canceled. Inspect native stderr for scheme-task delivery exceptions as well; a permanently frozen host JavaScript thread requires the external test runner to enforce the deadline.

## Touch regression tests

The lifecycle fix was verified on a real iPhone after several background/foreground cycles: the main web view no longer stops responding to touch after returning from the background, which previously logged the WebKit warning "Touch event gesture recognizer failed to reset after ending gesture deferral".

The shared `SecondaryTouch` Xcode scheme launches `www/secondary-touch-host.html` with a transparent main web view and dialog above the secondary. `SecondaryTouchUITests` covers four Home/reactivate cycles, two app switches while a finger is held, an update during a short held tap (the main click is suppressed and the next tap reaches the secondary), an idle update (no page touch cancellation), a short held tap without an update, and a main-only lifecycle control. The held-background case arms the sample app to open Settings through the public `UIApplication.openSettingsURLString` during the held touch, then asserts that the app entered the background. This avoids concurrent XCTest gestures, which cannot synthesize a Home-button press while a finger is held. `CDVViewControllerTest.testSecondaryTouchCancellationLifecycle` separately checks terminal transitions, reset cleanup, idle updates, and lifecycle enable/disable state. Lifecycle tests allow one second after activation for the simulator's WebKit viewport/accessibility state to settle.

Run `xcodebuild test -workspace tests/cordova-ios.xcworkspace -scheme SecondaryTouch -destination 'platform=iOS Simulator,id=<simulator-UUID>' -parallel-testing-enabled NO`. Device runs require signing and UI automation enabled. With an SDK whose minimum supported deployment target exceeds the repository's target, use a temporary `-xcconfig` deployment override for the test build; the platform's deployment target is unchanged.
